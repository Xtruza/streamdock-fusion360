# Architecture

## Decisions

| Concern | Decision | Reason |
|---|---|---|
| StreamDock integration | Official Node.js V2 Plugin SDK | Native `.sdPlugin` lifecycle, WebSocket events and Property Inspector |
| Hardware driver | Excluded | The Device SDK is for direct hardware control, not marketplace plugins |
| Primary execution | Optional Fusion Python add-in | Uses official `CommandDefinitions.itemById(...).execute()` on Fusion's main thread |
| Fallback | Configurable OS shortcut | Works before the add-in is installed and survives Fusion install-path changes |
| Discovery | User-home bridge file | Cross-platform and independent of Autodesk installation folders |
| Local security | Loopback-only server plus 256-bit random token | Rejects unauthenticated local requests and never exposes a network listener |
| Page navigation | Native StreamDock folders/pages | Avoids undocumented page-switching messages |
| Icons | Original SVG generated by Xtruza | Legally reusable and resolution-independent |

## Execution flow

In `auto` mode the Node plugin tries the authenticated localhost bridge first. If Fusion or the add-in is unavailable, it sends the configured shortcut only after verifying that Fusion is the foreground app. `api` and `shortcut` modes make either path strict.

The bridge receives HTTP on a worker thread and fires an Autodesk `CustomEvent`. Its handler runs on Fusion's main thread, resolves the editable command ID through `UserInterface.commandDefinitions.itemById`, executes it, and returns a bounded response.

## Known uncertainty

Autodesk documents command lookup and execution but does not publish a stable exhaustive list of every native command ID. Preset IDs are therefore editable in the Property Inspector and must be verified against the currently installed Fusion build before the first stable release.
